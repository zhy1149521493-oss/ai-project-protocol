# Skill 安装与调用

**中文（默认）** | [English](SKILL-INSTALLATION.en.md)

本指南用于安装和读取 `ai-project-protocol`。当前制度为 [1.3](../PROJECT-EXECUTION-PROTOCOL-ENGINEERING.md)；该工程文档是采用实例内的唯一权威规则。安装或读取 Skill 不代表已经授权开展具体项目。

## 完整包与单一来源

保留整个仓库的目录结构，至少保证 [Skill 入口](../SKILL.md)、[详细工程版](../PROJECT-EXECUTION-PROTOCOL-ENGINEERING.md)、[用户简明版](../PROJECT-EXECUTION-PROTOCOL-USER.md)、[决策模板](../DECISION-LOG-TEMPLATE.md)及其相对引用均可读取。不要只复制入口文件。

选择一个维护目录作为共享制度包的来源。若当前环境支持链接安装，可以将发现目录中的入口指向这个完整目录，避免独立维护两份规则。使用链接时，来源目录必须持续可访问；移动或删除来源会使链接失效。若采用复制安装，应明确更新来源与所安装版本，避免分别编辑两套规则。

具体项目的状态属于用户明确选定的项目实例，不写入共享 Skill 模板；更新共享包不会自动迁移已经采用的实例。

## 安装前检查

1. 根据当前宿主提供的设置、能力或[官方 Skill 文档](https://learn.chatgpt.com/docs/build-skills)，确认实际搜索目录及是否支持链接；不要假定某个主机路径适用于所有环境。
2. 检查目标目录中是否已有同名 `ai-project-protocol`，核对其来源和版本，不覆盖未经检查的文件。
3. 将完整包放入已确认支持的位置，或按宿主支持的方式链接完整来源目录。这里不要求修改全局系统设置。
4. 检查入口的相对引用，确认工程版、用户版、模板可完整读取，版本与维护来源一致。

## 调用与手动读取

如果宿主已经发现该 Skill，可在其支持的调用界面选择 `ai-project-protocol`。是否自动发现、何时刷新以及能否按短名称调用，需要在当前环境实际确认，不能由本指南或结构检查推定。

无法自动加载时，可以让执行 Agent 直接读取入口的绝对路径。将下列占位替换为完整制度包的实际位置：

```text
请读取 <完整制度包绝对路径>/SKILL.md，
沿相对引用完整读取工程主文档至末尾，核对当前制度版本及是否绑定项目。
此次仅做只读检查，解释主要规则，不启动应用项目，不写项目状态、路线或预算。
```

例如，在 Windows PowerShell 中手动读取入口（路径仅为示例）：

```powershell
Get-Content -LiteralPath 'C:\skills\ai-project-protocol\SKILL.md' -Raw -Encoding utf8
```

预期结果是入口文本可读；还需按其引用读取完整工程主文档。工具输出若被截断，应连续分段读到文件末尾。读取成功不等于自动加载成功。

## 无副作用验证

先在只读范围内确认以下结果，不创建项目路线或消耗应用项目预算：

- 入口和依赖都存在，能够完整读取，安装路径与选定来源对应。
- 执行 Agent 能指出当前工程版的权威地位及未绑定状态。
- 同一主工程轮次内的子 Agent、工具、测试和内部修复不额外计轮；后续独立主工程指令正常计轮。
- 达到工程预算上限时按制度申请，任务授权不会自动增加预算。
- 完整任务授权允许范围内的正常修复，但不会覆盖未批准的风险、资产或操作。

记录当前环境实际观察到的读取、发现和调用结果，分别说明成功与未验证部分。纸面回答与结构检查不证明长期执行效果，也不授予项目权限。只有用户另行授权采用制度并完成相应前置审批后，才进入具体项目工作。
