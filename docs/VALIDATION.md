对象：2.0.0-rc1；基线：1.3、提交 `eba4bd0060e6328db635d306b6b18fedeb824949`。仅验证通用制度候选，不做应用工程或修改实例。采用决定仍待用户。

## 完整读取与对应审查

主要执行者完整读取现行工程版、Skill、用户版、模板与索引；内部不同执行上下文的复核者完整读取工程版、模板、D-0001～D-0003 和相关审查材料，遇到截断已补读。源仓库 main 的 API 引用与基线提交一致。旧包15文件原始字节归档，校验见 [BASELINE](BASELINE.json)。

先建立 [CHANGE-MAP](../REFERENCE/CHANGE-MAP.md)，再写候选规则。内部对应复核发现两个遗漏：高风险执行的预定复核触发，以及关键必要前提/成功条件改变的重大认定。已经补回 CORE §2/§5，审查者复核确认修正；其余预算、用户理解核对、轻量条件、历史保护及旧效果检查节奏均保留。没有以“压缩”名义默删上述约束。

## 独立纸面场景

内部不同执行上下文实际按候选入口完整读取必需文件，并按相关性读取记录格式和迁移说明，逐项给出了12个场景的预算、继续/停止、批准及条款依据。未执行工程、扣账或改变文件；以下为其纸面解释与规则的核对结果，不是软件运行或长期遵从测试。

| 场景 | 实际纸面应答核对（12项一致） |
| --- | --- |
| 第5轮正在执行，仅 Agent 的两小时估计到点 | 内部估计不是硬停；R=0不自动终止当前轮，可在范围/安全资源条件内完成 |
| 同一未结束第5轮因真实容量限制暂停，重连续接 | 先保存/完整重读核对，原W、U=5不重复扣；资源未恢复不能绕过 |
| 第5轮已经结束，用户新要求独立修Bug | 新指令需新轮，但R=0，先复盘并获追加，不能倒改原轮暂停 |
| 已授权测试失败，修复涉及未授权全局配置，另有独立安全测试 | 普通失败不取消授权；越界项及真实依赖停，其他获准工作继续 |
| 同P第2次普通申请＋2，未触发重大取舍 | 实质复盘及用户批准必需，不因偶数强制三轮；批准后C=7、U=5时R=2 |
| 第1次申请同时放弃重要成果换架构，重要反方异议未解 | 重大独立审查及用户理解/二审核准；未解重大分歧升级多轮，奇数不降级 |
| 旧证据完整覆盖与部分覆盖 | 前者引用复用；后者只补缺口/受影响范围，不全盘重做或虚报覆盖 |
| 连续两轮排除不同关键假设，未有验收通过 | 新排错证据可以是进展，不机械按“无通过”认停滞；其他硬预算仍有效 |
| 迁移把U=5旧步骤重新给5轮，或切轻量清未解P | 拒绝清账，保留原预算、P/B、路线和授权，新增预算需明确批准 |
| CORE 输出只读到一半但 STATE 有余额 | 必须补读到末尾；余额不能代替完整读取门槛 |
| 有不可逆操作授权，但路线规定的独立执行复核缺失 | 不能把该检查点写通过或继续依赖动作；其他独立安全工作继续 |
| 主要交付标题没变，改变决定成功的关键前提 | 仍属重大，不能用未改标题规避反方审查及用户批准 |

独立应答指出“耗尽复盘”究竟在最后一轮开始还是收尾进行仍可能被误解。CORE §4 已明确：最迟在用尽额度的轮结束/真实停止交接时做，更早申请则提前；不因R=0中途停工，容量不足先存待补项并在同W恢复补齐。修正后独立执行者复核场景1/2/3，确认未放宽预算、授权或结单边界。另两项场景边界予以保留：新Bug是否属于原S/P须按实际范围判断，不能自动赠送5轮或一律归旧步；高风险复核按ROUTE预定时机及真实依赖执行，不擅自将全部复核改成统一前置审批。
