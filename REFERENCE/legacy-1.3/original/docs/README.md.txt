# 文档索引

## 用途与已实现范围

本制度包为复杂 AI 辅助项目提供可复用的执行规则，涵盖成果验收、路线压缩与审批、主工程对话计数、有界追加预算、用户参与、证据复用、因果决策记录及交接。工程对话轮次、内部工作量、实际资源成本与交付结果分别记录；内部子 Agent 和并行任务不额外消耗轮次。制度包包含文档和 Skill 入口，不包含应用程序、强制执行服务或具体应用项目计划。

自制度 1.2 起，每个路线步骤都以第一轮工程对话完成整步交付为目标。后续轮次用于实际测试、缺陷及共同根因修复、回归、验收，或针对第一轮真实阻断进行有界恢复。五轮是预算上限，不是将主要开发分摊到多轮对话的进度表。

制度 1.3 增加完整任务授权：已批准的操作、资产和风险边界可以覆盖必要的执行、测试、修复、清理及恢复验证，无须按动作重复索取授权。正常失败可以在原授权范围内继续修复；仅停止越界操作及其真实依赖，其他独立安全、已获授权且有可用预算的工作继续。原有轮次计数及审批关口保持有效。

## 安装与使用

前置条件：Markdown 阅读工具，以及能访问这些文件的 Agent。没有应用构建或运行依赖。Python 和 PyYAML 仅供可选的内置 skill-creator 校验器使用，遵循制度本身不需要它们。

1. 阅读用户简明版和详细工程版。本交付明确为未绑定项目的通用模板，不授予任何应用工程授权。
2. 用户授权将制度用于具体项目后，选择一个专用实例目录，复制完整制度包，不覆盖已有项目文件。保持三份制度/模板文件及其相对链接完整，在工程版第 13 节填写权威实例路径和采用版本。
3. 填写项目实际目标、可观察的验收条件、资源、角色、完整路线和当前状态。实施前完成路线审批。核对适用性后保留已有证据和决策历史。
4. 每条独立主工程指令按工程版第 9 节执行，结束后同步同一份工程版和用户简明版。内部委派共享该主轮次的 W-ID，不另行预留或消耗轮次。上一轮提交结果后，或因必须获得新指令/批准而暂停后，新收到的独立用户工程指令开始下一轮；单纯行政审批不计工程轮次。仅在触发条件成立时创建实际决策记录；模板本身不是实际档案。

在 Windows PowerShell 中，从实例目录手动读取：

```powershell
Get-Content -LiteralPath '.\PROJECT-EXECUTION-PROTOCOL-ENGINEERING.md' -Raw -Encoding utf8
```

预期结果：完整主文档可读。若工具截断输出，应连续分段读到文件末尾再开始工作。随后要求 Agent 遵循该确切实例，核对路线和预算，并在结束时更新状态。工程版提供可复制的手动提示词。

安装完整制度包前，应核对目标宿主的实际搜索目录、同名冲突和权限。保持单一维护源与完整依赖，不以本机结果推断其他环境已经加载成功。操作方法和只读检查见[安装与调用指南](SKILL-INSTALLATION.md)。共享安装保持未绑定模板，项目状态仅写入选定的项目实例。

## 配置与维护

在工程版第 13 节配置项目 ID、实例路径、模式、制度/路线/状态版本、验收、重要性阈值、角色及预算台账。完整模式采用工程版定义的初始参数，不得在 Skill 或用户简明版中另行改动。轻量模式须满足规定的适用条件。

先修改权威工程版，再同步受影响的用户说明和模板字段，并检查 Skill 链接。已有项目实例在明确迁移决策前保持原采用版本；共享制度包更新不等于批准修改项目规则。已确认的决策正文不可改写；后续结果通过追加事件或链接新的后继决策记录。

## 开发与验证

文档修改应检查本地 Markdown 链接和锚点、代码围栏配对、必填字段、数值规则一致性、预算继承及审批顺序。修正后仅重跑受影响检查。本制度包没有专用文档格式检查器、链接检查器或应用测试套件。

如已安装内置 `skill-creator`，可用其 `scripts/quick_validate.py` 校验制度包目录。Windows 上使用 Python UTF-8 模式，确保中文路径和正文读取一致：

```powershell
# 将校验器路径替换为本机实际安装位置。
python -X utf8 'C:\path\to\skill-creator\scripts\quick_validate.py' '.'
```

预期结果为 `Skill is valid!`。该检查验证入口结构，不证明 Agent 实际遵从或项目制度效果。历史结构检查保留在审查报告中，目标宿主的加载检查方法见安装指南。未运行任何实际应用项目。
